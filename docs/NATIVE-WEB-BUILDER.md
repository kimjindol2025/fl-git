# Native web bundle builder (developing)

scripts/fl-front-build-native builds a separate Native web bundle from a web
source directory. It creates a fresh output child, stages pages/islands/public,
runs the Native FLP compiler when contracts exist, parses source without
executing it, emits CSS/FreeLang/browser modules, and links a Native server.
The original source tree is read-only during the build.

## Required tools

Set FREELANG_NATIVE_COMPILER to the verified Native compiler and
FREELANG_NATIVE_WEB_TOOL to the matching executable compiled from
tools/fl-front-build.fl. FREELANG_NATIVE_RUNTIME_ARCHIVE and
FREELANG_NATIVE_RUNTIME_INCLUDE must describe that compiler's current runtime.
Supply FREELANG_NATIVE_FLP_TOOL when the project contains .flp contracts.
The existing FLP compiler implements the current shop contracts; unsupported
contracts fail. A project containing only .flx source does not require FLP.

~~~sh
scripts/fl-front-build-native "$WEB_SOURCE" "$EXISTING_OUTPUT"
FREELANG_NATIVE_WEB_APP="$VERIFIED_BUNDLE/web/app-native" scripts/fl-web-run-native
~~~

The output directory must be outside the input web tree. Missing tools fail
explicitly. There is no binary search, Node fallback, download, install or
system configuration change. The Native SDK still needs its documented
link/runtime dependency environment. Build failures retain their private
artifacts. A PASS completion marker means compilation/linking passed; it is
not browser, complete application or commercial acceptance.

Both entries lower an unlimited/higher virtual-memory limit to 2 GiB and
preserve a smaller inherited limit. They disable core files. Heavy verification
uses ps followed by the shared flock; the protected runners and
their time limits are unchanged.

## Source and asset behavior

tools/front-source.fl spells supported freelang.ast.v1 nodes back into
FreeLang. Invalid literals, odd maps, unsupported kinds and unknown fields
fail explicitly. Source quotes/controls/Unicode are escaped; isolated UTF-16
units use escaped JSON data. Full advanced grammar equivalence is not accepted.

tools/front-web.fl handles deterministic discovery, helper ordering, route
names, static imports, styles, source-map entries and island placeholders.
Static imports resolve within the original project or the private bundle.
Duplicate routes/global names and missing render functions fail. There must
be at least one real route. Nested helpers, ns/defstore, and local SSR h
bindings that are not supported fail rather than become empty code.

SSR h calls use a FreeLang server helper with an explicit children array, so
all supplied children are retained. Attributes are escaped and function values
belong in islands. SSR child strings retain the existing trusted-markup
contract; application data must use the appropriate HTML escaping helper.
The existing error-overlay layout and hint are retained, with escaped route
and error values.

Template marker substitution is separate from helper/API/global data and
attribute-map literals. Rendering strings reserve ISLAND_PLACEHOLDER[_N] and
ISLAND_SCRIPTS. A placeholder with no client and a client with no script
marker fail explicitly. Island AST normalization, CSS bindings and browser
emission reuse the existing Native components; unsupported stores/watch
options remain explicit errors.

Browser modules and CSS use content-addressed URLs. The builder hashes
generated bytes, seals the asset names, regenerates the server references,
then checks every expected GET/POST wrapper declaration and asset digest
before C generation. Existing compatibility app.css remains available.
The request launcher binds only 127.0.0.1; the generated binary also rejects
an unspecified/non-loopback bind environment before startup effects.
The complete bundle must accompany its executable.

Framework static page registrations precede helper dynamic registrations;
dynamic pages and the final 404 follow the source body. This preserves the
intended /order/track priority over the helper's /order/:id. Broader manual
registration/collision and advanced import/scope cases remain to be verified.
