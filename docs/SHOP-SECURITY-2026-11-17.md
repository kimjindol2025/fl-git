## 수정 계약

| 항목 | 실제 구현 |
|---|---|
| 장바구니 | CSPRNG 32바이트 세션, HttpOnly/SameSite=Strict 쿠키, `data/cart-<세션>.json` 분리. 요청에서 형식을 검증한 세션만 사용한다. 주문 성공 뒤 그 세션만 비운다. 여러 프로세스와 정상 재시작에서도 파일을 공유한다. |
| 주문·관리자 쓰기 | `data/.commerce-lock`의 원자적 mkdir로 프로세스 간 배타 처리. 상품 확인부터 재고 계산·주문 파일 게시까지 한 임계 구역이다. 관리자 상품 수정과 주문 상태 변경도 같은 잠금에 참여한다. 잠금 중 요청은 503으로 거부한다. 재고 부족은 400이다. |
| 파일 게시 | 임시 파일에 JSON 쓰기, 읽기 대조, 0600 권한, 파일 fsync, 같은 디렉터리 rename, 디렉터리 fsync. 주문은 두 파일의 새 상태를 `commerce-journal.json`에 먼저 남긴 후 게시한다. 저널이 있으면 읽기는 저널 상태를 사용하고 다음 쓰기가 먼저 반영한다. 기존 파일이 손상되면 기본 상품/빈 주문으로 조용히 바꾸지 않는다. |
| 관리자 인증 | `FL_ADMIN_PASSWORD`만 사용한다. 입력과 기준을 SHA-256으로 고정 길이 해시한 뒤 기존 `hash_eq`의 timingSafeEqual로 비교한다. 원문 암호는 파일·로그에 기록하지 않는다. IP별 5회 실패 뒤 15분 차단하고 상태를 파일에 보존한다. |
| 관리자 화면 | 실제 페이지 핸들러도 인증 검사한다. `/login/admin` 폼 → `/api/admin/login`으로 1시간짜리 난수 쿠키를 발급한다. 저장되는 세션 식별자는 해시다. `/api/admin/logout`은 서버 세션을 무효화하고 쿠키를 만료한다. 인증 응답은 no-store다. |
| 주문번호·조회 | 24바이트 CSPRNG를 붙인 주문번호. IP별 및 주문번호별 실패 카운터를 파일에 보존한다. 1분 동안 10회 실패하면 이후 요청은 429이며 성공 자격을 검사하기 전에 제한을 적용한다. 잘못된 주문번호/뒤 4자리는 같은 404 응답이다. 응답 필드는 상태·시각·상품·합계뿐이다. |

`FL_SHOP_LOCAL_HTTP=1`은 이번 로컬 HTTP 시험에서만 Secure 쿠키를 해제했다. 기본값은 Secure다. 실제 운영 연결은 HTTPS가 필요하다. `FL_GIT_REPO`는 저장 루트를 지정하는 기존 환경변수다. 민감 저장 파일·저널·카트·임시 파일은 Git 제외 목록에 추가했다.

운영자가 확인하지 않은 오래된 잠금은 자동 삭제하지 않는다. 미완료 저널·동기화 오류가 있으면 요청을 성공으로 계산하지 않는다. 미완료 주문 이후의 클라이언트 재시도·중복 주문에 대한 idempotency 계약은 별도 과제다. 세션·만료 제한 기록의 장기 청소/용량 정책과 분산 호스트 환경은 추가 검증이 필요하다.
