# Native JavaScript execution foundation

The SDK can execute generated JavaScript using the installed platform's
SpiderMonkey ESR115/GJS library pair. `native/js-engine.c` provides the process
and file boundary. FreeLang remains the implementation language for adapters
and frontend policy. No new handwritten JavaScript runtime is included.

This supplies the engine needed for the headless migration. The initial foundation did not implement the Island runner. The subsequent
[standalone Native entry](NATIVE-ISLAND-HEADLESS.md) now implements the virtual
DOM, selection, click/dispatch and result protocol in FreeLang as an experimental
path. Full compatibility, the test-file gate and `/~ai/test` integration remain
unqualified. Their metadata remains `NOT_RUN`, and default `scripts/fl-dev` is
unchanged.

## Generated runtime modules

The compiler accepts a separate FreeLang runtime module:

```bash
"$FREELANG_NATIVE_COMPILER" --browser-runtime-js runtime.fl program.fl program.js
"$FREELANG_NATIVE_JS_ENGINE" "$FREELANG_NATIVE_MOZJS_LIBRARY" \
  "$FREELANG_NATIVE_GJS_LIBRARY" program.js -- 'literal argument'
```

The runtime module is compiler/host implementation input, separate from the
user program. It can use the existing compiler-only `j-host-*` primitives. User
program validation still rejects those primitives and the private core names.
Ordinary `--browser-js` keeps its existing interface and generated bytes in the
verified comparison corpus. Both direct inputs are protected against canonical
input/output path equality, and output suffix validation is unchanged.

An adapter can expose output without embedding JavaScript source:

```clojure
(defn host-print-json [value]
  (j-host-call (j-host-at (j-host-global) "print")
    [(j-host-json-stringify value)]))
```

The C engine host accepts explicit absolute paths to the two runtime libraries,
a regular generated script, and literal arguments after `--`. It propagates
execution failure, preserves lower inherited memory limits and caps its process
at 2GiB. It sets a process-local UTF-8 character locale before library loading;
otherwise GJS printing from a C embedder can replace non-ASCII characters.

SpiderMonkey's public `DisableJitBackend` API is called before loading GJS,
whose initializer starts the engine. This selects interpreter execution and
disables JIT and WebAssembly. The installed ordinary GJS console failed JIT
initialization under the same cap; that failure is retained. No limit was raised,
and no library or system configuration was patched. See the pinned
[SpiderMonkey initialization API](https://raw.githubusercontent.com/mozilla/gecko-dev/esr115/js/public/Initialization.h)
and [GJS context API](https://raw.githubusercontent.com/GNOME/gjs/1.80.2/gjs/context.h).

## Packaging and verification

Packaging always includes `fl-js-engine`. Supplying both
`FREELANG_NATIVE_MOZJS_LIBRARY` and `FREELANG_NATIVE_GJS_LIBRARY` additionally
bundles their exact files, checks their supported SONAMEs, records input hashes
and includes the copies in `SDK.SHA256`. Activation resolves the host and both
libraries from the relocated SDK. Without that pair the package remains a core
tool bundle; it does not automatically search for an engine or fall back to
Node. The platform's other GJS dependencies remain system requirements.

[The receipt](evidence/native-headless-engine-20261120.json) distinguishes:

- Fresh unchanged-seed bootstrap with Stage 2 = 3 = 4 C, within the existing
  generation time/RSS bounds; relocated compiler self-generation matches it.
- Generated FreeLang runtime/module execution, closures, loops, prototypes,
  literal argument boundaries, UTF-8 output and private Node value comparison.
- Existing default browser output byte comparisons and unchanged user-code
  restrictions, malformed-input handling and direct source/output protection.
- Engine exception/syntax failures, library configuration, relocation, actual
  bundled-library loading and manifest tamper/restore controls.
- Existing frontend unit, CLI and FX regressions, with the original tracked and
  foreign-inclusive cohorts reported separately.

The first single generation smoke probe omitted the outer memory cap/build
lock and is excluded from qualification. Its identical input was then generated
under the original 2GiB cap, shared lock and 15-second bound. The initial C host's
Unicode replacement failure is also retained; final output must equal the
complete expected JSON. Private Node execution is an oracle only, outside the
audited Native product traces. Protected tests, expected values, runners and
bounds are unchanged.

This checkpoint does not qualify Island headless behavior, actual application
or Git UI flows, current whole DB safety/operations, or commercial readiness.
The overall goal remains active, commercial status is HOLD, and production
deployment has not run.
