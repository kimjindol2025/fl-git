# Node 제거 진행 기준

1차 목표는 FX·DB95·프론트·앱의 필수 빌드와 실행을 Node 없이 수행하는 것이다.
기존 기능과 검증 기준을 보존하며, 실제 운영 배포는 별도 승인 전까지 하지 않는다.
이 표는 완료 선언이 아니라 남은 기본 경로를 명시하는 작업 목록이다.

현재 새 Native 도구로 실제 앱을 빌드하고 실행할 수 있다. 기존 기본 Node
진입점은 아직 남아 있으므로 Node 제거 완료는 아니다. 새로 작성한 JS 파일과
JS 줄 증가는 0이다. 생성된 브라우저 자산은 Native 컴파일러의 출력이다.
사용자 프로젝트가 선택적으로 요구하는 외부 개발 도구와 제품 자체의 필수
런타임 의존성은 검증 보고서에서 구체적인 실행 경로별로 기록한다.

NATIVE-WEB-BUILDER.md가 웹·런타임 연결의 최신 근거를 기록한다.
각 Native 도구의 상세 계약과 제한은 해당 NATIVE-* 문서를 따른다.
시각·요청 IP와 JSON 응답 상태 수정은 새 bootstrap/core/HTTP 검증을 통과했다.
FX의 NATIVE-TIME-PEER.md·NATIVE-JSON-STATUS.md와 웹 문서가 근거를 기록한다.

실제 브라우저 검증은 NATIVE-BROWSER-VERIFICATION.md에 기록했다. 기존 로컬
Orca 내장 엔진에서 8개 섬 마운트, 실제 카트 클릭 1→2, 상품 3개의 값·이름
UTF-8 바이트 차이 0, 스크립트 삽입 요소 없음, 콘솔 오류 0과 모바일 390px
넘침 없음을 확인했다. 빌드·서버·단위 시험 경로의 Node 실행은 0이었다.
관리자 변경·주문 저장·전체 Git UI·외부 provider 동작은 아직 NOT_RUN이다.
이전 브라우저 시작 실패와 도중 발견한 실패 사례는 최종 통과와 구별한다.

기본 웹 명령 전환의 근거는 NATIVE-DEFAULT-WEB.md에 기록했다. 기존 빌드 후
실행 동작을 유지하며, 명시한 Native SDK만 사용한다. 기본 명령으로 빌드한
앱 SHA는 앞선 브라우저 검증 앱과 같았다. 설정 차단 17건, HTTP 관찰 19건,
실제 브라우저 8개 화면과 카트 클릭을 확인했다. Node 실행은 0이었다.
별도 진단기의 HTTP 응답 분류 오류와 공유 잠금 대기로 미실행인 추가 검사는
통과 항목과 구별한다. fl-dev와 .freelang/deploy.sh는 아직 Node를 사용한다.

DB 전체 Native 기준의 기록값은 51 PASS / 20 FAIL이며 현재 전체 재실행은
NOT_RERUN이다. 기존 Native 러너에는 미이식 JS/shell 사례를 명시적으로 실패로
남기는 경로가 있다. 사례를 삭제하거나 이름만 바꿔 통과시킬 수 없다.
새 DB writer는 이전 테이블 페이지를 덮어쓰지 않고 새 세대를 기록한 뒤
원자적으로 manifest를 게시한다. FX 4fa975b2390db7773997b1853f225f8de6085d37의
fd_publish와 DB 380404886129bf681782bac3c73e08fd0595a996의 구현이 근거다.
동일 상태 기록 15건과 실제 WAL 추가 변경 13건을 검증했다. 여기에는 같은
12개 장애 지점을 두 상태에서 실행한 24건의 복구와, 고의 손상 2건의 오류
거부가 포함된다. 매 장애 뒤 별도 프로세스에서 두 번 복구했고 이전 세대
페이지와 필요한 WAL을 보존했다. Native 사례 11/12/42와 기존 독립 reader도
변경 없이 통과했다. 상세는 DB의 NATIVE-CHECKPOINT-GENERATIONS.md와 FX의
NATIVE-FD-PUBLISH.md를 따른다. 새 compiler의 ELF SHA는
e28b5062811fe1d65125e4d37f77b3f791fca85586fd2985c84d5ef1ceb39c5c이며,
고정점 Stage2=3=4, 프론트 71/71, CLI 22/22, FX 11/11과 기존 소스의 DB
7/13/36/40 언어 회귀도 통과했다. 기본 웹의 마지막 브라우저 검증 SDK는
NATIVE-DEFAULT-WEB.md에 별도 기록하며, 새 SDK로 전체 웹 재빌드는 NOT_RUN이다.

WAL 후속 수정은 DB ed908d2c461f39c4bfc554783975f9f8bcc6fb2e에 저장했다.
유효한 checkpoint와 맞지 않는 WAL의 부재·빈 파일·잘린 prefix·다른 이력을
조용히 빈 상태로 처리하던 문제를 오류로 거부한다. WAL 생성은 0600을 쓰고,
파일과 부모 디렉터리를 동기화하며 오류 경로에서도 핸들을 닫는다. 복구 중
오류가 나면 변경 전 논리 상태를 복원한다. 기존 Native에서 실패한 계약
22건을 포함해 25/25와 위험 문자·Unicode WAL 4/4가 통과했다. 체크포인트
회귀 28건, 기존 사례 11/12/41/42와 독립 reader도 새 SDK에서 재확인했다.
범위는 TCP 저장 경로이며 다른 저장 모듈 전체의 안전성을 뜻하지 않는다.

기존 3,200건 WAL 복구 시험은 수정 없이 Native에서 통과했다. 이 시험을
막은 str_join_lines를 FX 4dee8bca2430846e6cc524ff56f9bc237be9cfbc에서
구현했으며 공개 계약 24개도 검증했다. compiler ELF SHA는
eb23e2039163794c641d2f3f3f076ddf5cd3e3d6bff5800216ab638e39d2361b다.
Stage2=3=4와 프론트 71/71, CLI 22/22, FX 11/11, checker 32개와 기본 검사,
기존 DB 7/13/36/40 언어 회귀가 통과했다. 전체 웹·브라우저의 마지막 검증
SDK는 여전히 앞 문서를 따르며 이 SDK로 전체 웹 재빌드는 NOT_RUN이다.
DB 상세 근거는 NATIVE-WAL-SAFETY.md, FX는 NATIVE-JOIN-LINES.md에 있다.

이전 C 생성의 39.14초·42.36초 중 두 번째는 40초 기준에 미달했다. 이
기록은 보존한다. 후속 FX 48988a3756f2c0520be7121021c54083aaafb62a는 연산자
이름·함수 번호를 유지하면서 조회에 정적 인덱스를 쓴다. 기존/변경 런타임의
조회 계약 2,673건과 동시 조회 32,768건의 결과 차이는 0이다. 같은 정식
seed→Stage4 빌드에서 34.08초·35.95초, 최대 RSS 1,526,584 KiB로 시간·메모리
기준을 통과했다. Stage2=3=4 및 이전 생성 C와도 바이트가 같다. compiler
ELF SHA는 e966e6342053c48fdd3af001a029e0d4a4923832f5122f0f300696ce8d1b2c94다.
FX의 NATIVE-OP-LOOKUP.md가 상세 근거와 재시작 중단/이어서 실행한 기록을
담는다. 마지막 3,200건 시험의 C 링크만 재시작 때 중단됐으며, 생성된 C를
재사용해 같은 소스·옵션·제한으로 컴파일/실행을 마쳤다. 원래 다섯 PASS 줄과
복구 전후 행 수·해시 일치를 확인했다. 이전 통과 사례는 반복하지 않았다.

이 SDK의 프론트 71/71·CLI 22/22·checker 32/32는 HEAD b6d443a 기준의 기존
시험 결과다. 이후 별도로 관측한 프론트 변경 4개와 추가 시험은 그 결과의
범위에 포함하지 않는다. 전체 웹·브라우저를 이 SDK로 다시 검증하지 않았다.
실제 Native TUI는 ASCII 커밋 1건 통과, Unicode 입력과 Git C-quoted 경로
클릭 stage 2건 실패다. 세 프로세스 모두 종료 0·터미널 복원은 확인했지만
사용자 동작의 값 차이/미반영으로 검증기는 종료 1이다. 이 실패를 숨기지
않고 기본 CLI의 Node 경로를 전환하기 전에 고친다. 다른 프론트 작업은
수정하거나 이번 문서 커밋에 포함하지 않는다.

commit 중 I/O 실패 뒤 live 상태와 명시적 건강 상태, 프로세스 소유권,
이미 손상된 레거시 checkpoint의 복구와 안전한 세대 회수는 남아 있다.
새 세대와 실패 후보는 아직 자동 삭제하지 않아 디스크 사용량이 제한되지
않는다. 전체 Native 71개는 이 변경 뒤 재실행하지 않았고, 51/20은 이전
소스의 기록값이다. DB 상용 준비 판정은 HOLD이며, 고객 DB 연결·주문 저장·
운영 배포는 하지 않았다.

후속 기본 CLI 전환은 NATIVE-DEFAULT-CLI.md에 기록했다. 기본 fl-git가 Native
launcher를 실행하고 SDK 부재 시 종료 2로 실패한다. 앞서 기록한 TUI Unicode
입력/인용 경로 실패는 수정됐다. Git 실제 출력의 경로 28건, 잘못된 경로
거부 6건, 기본 명령의 TUI 16건, CLI 22건과 기존 7개 suite 71건이 통과했다.
Escape/Ctrl-C는 입력을 취소하고 NUL 오류는 종료 1이다. 모든 PTY 사례에서
터미널이 복원됐다. 다른 웹 변경 4개와 추가 미추적 시험은 보존했으며 이
단위 결과 범위에 포함하지 않는다. 전체 웹/브라우저와 인증 provider 쓰기는
이번 변경의 검증 결과가 아니다. checker·test·dev 및 공통 배포의 기본 Node
경로가 남아 있어 Node 제거 전체는 미완료이며 DB 상용 준비도 HOLD다.

기본 시험 명령도 NATIVE-DEFAULT-TEST.md의 근거로 Native 전환했다. 통과 수와
전체 수가 다른 요약을 받아들이던 판정을 고쳤고, 새 기본 명령의 계약 26건과
기존 71건이 통과했다. 실제 기본 경로는 추가 미추적 시험까지 찾아 80/80을
통과했으며 그 소스와 다른 웹 변경 4개는 수정·커밋하지 않았다. 수치 경계의
합성 요약 문자열은 실제 실행한 단위 시험 수로 세지 않는다. Node 실행은
수집한 제품 경로에서 0이다. checker·dev·공통 배포 및 npm 경로와 DB 상용화
검증은 아직 남아 있으며 목표 전체는 계속 진행한다.

기본 페이지 검사 fl-check도 NATIVE-DEFAULT-CHECK.md의 근거로 Native 전환했다.
실제 입력 38건에서 Node 참조와 종료 코드 및 진단 출력 바이트가 일치한다.
Node 참조 실행은 비교용이며 제품 실행 경로는 Node 실행 0이다. 초기 비교용
옵션 실패 35건도 별도로 보존했고 유효한 비교의 통과 수에 넣지 않았다.
실제 오류 코드를 표식이 덮지 않게 고쳤고, 정상 프로세스의 중복·손상 표식은
BLOCKED로 처리한다. fix는 진단의 안내 필드이며 자동 수정 옵션이 아니다.
전체 목표와 DB 상용화 검증은 계속 진행하며 dev/HMR·공용 도구·배포 경로와
SDK 포장은 남아 있다.

기본 FLP 명령도 NATIVE-DEFAULT-FLP.md의 근거로 Native 전환했다. 두 페이지
검사를 거친 뒤 임시 공간에서 생성하고, 완전한 8개 결과를 확인한 다음 반영한다.
실제 읽기 전용 출력의 실패 전에 6개 파일을 바꾸던 문제를 재현하고 수정했다.
중간 후보의 종료 시 복구 누락도 보존했으며 수정 후 오류·종료·동시 편집 6건이
통과했다. 이는 잡을 수 있는 실패의 복구 근거이며 여러 파일의 동시 가시성이나
강제 종료·전원 장애의 원자성을 증명하지 않는다. Node 생성기 비교는 금지된
Node 빌드 단계이므로 미실행이며 기존 Native 생성 결과와 저장된 island 바이트를
비교했다. dev/HMR·공용 검증·배포와 DB 상용 준비 검증은 계속 남아 있다.
