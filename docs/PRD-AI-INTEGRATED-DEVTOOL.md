# fl-git AI 통합 개발도구 PRD

## 문서 목적

`fl-git`을 서버에서 사용하는 Git 관리 화면에서 AI와 함께 코드를 읽고,
수정하고, 검증하는 통합 개발도구로 확장한다.

현재 제품은 저장소 상태·변경 파일·커밋·원격·프로젝트 AIRC 문서를 AI 전달용
Markdown/JSON으로 제공한다. 이 PRD는 그 문맥 기능을 기반으로 AI 대화,
코드 검색, 승인 가능한 수정, 테스트 재실행, 편집기·터미널 통합까지의 제품
범위와 단계별 완료 기준을 정의한다.

## 제품 정의

### 한 줄 정의

저장소를 이해한 AI가 제안하고, 사용자가 승인한 변경만 적용하며, 테스트 결과를
바탕으로 다음 수정까지 연결하는 서버형 AI 개발도구.

### 핵심 사용자

- 서버에서 IDE 없이 여러 Git 저장소를 관리하는 개발자
- Codex·Grok·OpenCode 등 외부 AI에 저장소 문맥을 전달하는 개발자
- 원격 서버의 코드와 배포 전 변경을 안전하게 검토해야 하는 운영자

### 해결할 문제

- AI에게 현재 브랜치, 변경 파일, 프로젝트 규칙을 매번 설명해야 한다.
- AI 답변을 실제 코드 변경으로 옮기는 과정이 분리되어 있다.
- 변경 후 테스트·빌드·오류 재수정 흐름이 단절되어 있다.
- 서버 환경에서 코드, Git, AI, 실행 로그를 한 화면에서 확인하기 어렵다.

## 목표

1. 저장소 문맥을 유지한 AI 대화 제공
2. 파일과 코드 검색을 AI 도구 호출로 제공
3. 모든 코드 변경을 diff와 사용자 승인 뒤에 적용
4. 테스트·빌드 결과를 AI에 전달해 수정 루프 구성
5. 코드 편집기와 제한된 터미널을 같은 작업공간에 통합
6. 여러 프로젝트의 작업·권한·AI 변경 이력을 안전하게 관리

## 비목표

- VS Code 전체 기능과 확장 생태계 복제
- 사용자 승인 없는 commit, push, 파일 삭제, 원격 명령 실행
- API 키·GitHub 토큰을 저장소 파일이나 브라우저 저장소에 보관
- 완전 자율 에이전트가 서버에서 무제한 명령을 실행하는 구조
- 초기 단계에서 실시간 다중 사용자 공동 편집 제공

## 사용자 핵심 흐름

```text
저장소 선택
  → 현재 상태·규칙·변경 문맥 자동 수집
  → AI에게 질문 또는 작업 요청
  → 관련 파일 검색
  → AI 수정안 생성
  → diff 검토·승인
  → 파일 적용
  → 테스트·빌드 실행
  → 결과 분석 및 필요 시 재수정
  → commit·push는 별도 확인 후 실행
```

## 단계별 제품 범위

### 1단계 — AI API 연결 + 채팅창

#### 목적

현재 `ai-context`를 AI 모델 호출로 연결해 저장소를 이해하는 채팅을 제공한다.

#### 요구사항

- AI Provider 추상화: OpenAI 우선, 확장 가능한 provider 구조
- 모델·endpoint·응답 제한 설정
- API 키는 서버 환경변수 또는 OS 비밀 저장소만 사용
- 현재 저장소의 `ai-context`를 기본 시스템 문맥으로 연결
- 대화 세션 생성·초기화·중단
- 스트리밍 응답과 오류 상태 표시
- 요청에 포함된 문맥 범위 표시
- 긴 문맥의 크기 제한 및 민감정보 마스킹

#### 완료 기준

- 사용자가 현재 저장소 화면에서 질문을 입력할 수 있다.
- AI가 현재 branch, remote, 변경 상태를 근거로 답한다.
- API 키가 UI·로그·Git 파일·AI 응답에 노출되지 않는다.
- Provider 오류·timeout·rate limit이 사용자에게 표시된다.
- 채팅창 없이도 기존 Git 기능은 정상 동작한다.

### 2단계 — 파일/코드 검색을 AI 도구로 제공

#### 목적

AI가 필요한 파일을 직접 요청하고, 검색 결과를 근거로 답하도록 한다.

#### 도구

- `search_files(query, scope)`
- `read_file(path, start, end)`
- `search_history(query)`
- `get_git_context(cards)`
- `list_tree(path)`

#### 요구사항

- 기존 `ai-search`를 AI tool 호출과 연결
- 작업 트리 내부만 검색하도록 경계 설정
- `.env`, 토큰, 인증 파일 등 민감 파일 자동 차단·마스킹
- 검색 결과에 파일 경로와 줄 번호 포함
- 도구 호출 과정과 결과를 채팅에서 확인 가능
- 한 요청당 파일 수·바이트·호출 횟수 제한

#### 완료 기준

- AI가 저장소 전체를 무조건 전송하지 않고 필요한 파일만 검색한다.
- 답변의 코드 근거에 파일 경로와 줄 번호가 표시된다.
- 허용되지 않은 경로와 임의 셸 명령은 도구로 실행되지 않는다.

### 3단계 — diff 기반 코드 수정 및 승인

#### 목적

AI가 직접 파일을 덮어쓰지 않고, 검토 가능한 patch를 생성한다.

#### 요구사항

- AI 응답에서 unified diff 생성
- 파일별·hunk별 변경 표시
- 변경 전후 비교와 적용 대상 표시
- 전체 적용·일부 적용·거부
- 적용 전 작업 트리 변경 감지
- 적용 전후 해시 기록
- 실패 시 부분 적용 방지 또는 복구 제공
- 승인된 변경만 작업 트리에 반영

#### 완료 기준

- AI가 생성한 patch가 화면에서 확인된다.
- 사용자가 승인하지 않으면 파일이 변경되지 않는다.
- 외부 변경으로 patch가 낡으면 적용을 차단하고 다시 생성한다.
- 적용된 변경은 Git diff와 작업 기록에서 추적된다.

### 4단계 — 테스트 실행과 오류 재수정

#### 목적

코드 변경 후 검증 결과를 AI 수정 루프에 연결한다.

#### 요구사항

- 프로젝트별 허용 명령 설정
- 기본 검증: `./scripts/check.sh`, `npm test` 등
- 명령 실행 전 사용자 승인 정책
- stdout·stderr·종료 코드·실행 시간 표시
- timeout·출력 크기·동시 실행 제한
- 오류 로그를 AI 문맥에 선택적으로 전달
- 실패 원인 분석 → patch 생성 → 재검증 흐름

#### 완료 기준

- 승인된 테스트 명령만 실행된다.
- 실패 로그가 숨겨지지 않고 AI에 전달할 수 있다.
- AI가 수정한 뒤 재실행 여부를 사용자가 결정할 수 있다.
- 테스트 성공·실패가 작업 기록과 변경 상태에 남는다.

### 5단계 — 코드 에디터·터미널 통합

#### 목적

AI, 코드, Git, 실행 결과를 하나의 작업공간에서 사용한다.

#### 요구사항

- 파일 트리와 읽기·쓰기 가능한 코드 에디터
- 현재 파일의 AI 질문·선택 영역 수정
- Diff 탭과 원본/변경본 비교
- 제한된 PTY 기반 터미널
- 터미널 명령 승인·중단·출력 제한
- 변경 파일, 채팅, 테스트 로그 간 상호 링크
- 브라우저 새로고침 후 작업 세션 복구

#### 완료 기준

- 파일을 열고 수정하고 저장할 수 있다.
- 선택한 코드만 AI에 전달하거나 수정 요청할 수 있다.
- 편집기 변경과 AI patch가 충돌 없이 diff로 통합된다.
- 터미널은 저장소 root와 권한 정책을 벗어나지 않는다.

### 6단계 — 멀티 프로젝트·권한·작업 기록

#### 목적

서버에서 여러 저장소를 안전하게 운영할 수 있는 제품 수준의 기반을 만든다.

#### 요구사항

- 프로젝트 목록·최근 작업·별칭
- 사용자·역할·프로젝트별 권한
- 읽기, 편집, 테스트 실행, Git 쓰기, 원격 쓰기 권한 분리
- AI 대화·도구 호출·patch·승인·명령·결과 감사 기록
- 프로젝트별 모델·명령·민감 경로 정책
- 세션 만료와 동시 작업 충돌 감지
- 작업 기록 내보내기와 보존 기간 설정

#### 완료 기준

- 사용자는 허가된 프로젝트만 볼 수 있다.
- 권한 없는 파일 읽기·명령 실행·push가 차단된다.
- 누가 언제 어떤 AI 변경을 승인했는지 재현할 수 있다.
- 프로젝트 전환 시 문맥과 권한이 섞이지 않는다.

## 공통 안전 원칙

- AI는 제안자이며, 파일 변경과 원격 작업의 최종 승인자는 사용자다.
- `push`, `pull`, branch 삭제, reset, clean, 파일 삭제는 별도 확인한다.
- 기본 권한은 deny-by-default로 한다.
- 도구는 명시된 저장소 root 안에서만 동작한다.
- 비밀값은 문맥 수집·로그·diff·작업 기록에서 제거한다.
- 모든 외부 명령은 명령명, 인자, 대상 경로, 승인 상태, 결과를 기록한다.
- 작업 트리 상태가 바뀌면 오래된 AI patch와 실행 결과를 무효화한다.

## 초기 기술 방향

```text
Web UI
  ├─ AI Chat / Context / Diff / Test panels
  ├─ Session state
  └─ Approval dialogs
       ↓
API layer
  ├─ AI provider gateway
  ├─ Read-only repository tools
  ├─ Patch validation/apply
  ├─ Test runner
  └─ Audit log
       ↓
FreeLang AFJ + controlled host capabilities
  ├─ Git operations
  ├─ File operations
  └─ TTY/PTY operations
```

기존 `ai-context`, `ai-search`, Provider 모델, Git 승인 게이트를 재사용한다.
AI Provider 연결은 Git 실행 권한과 분리하며, AI 요청만으로 Git 쓰기나 셸 실행이
발생하지 않도록 한다.

## 성공 지표

- 첫 AI 질문까지 걸리는 시간
- AI 답변 중 저장소 근거가 포함된 비율
- 검색 도구 호출 후 유효한 파일 근거를 얻은 비율
- 생성 patch의 적용 성공률
- 승인된 patch의 테스트 통과율
- 테스트 실패 후 재수정으로 해결된 비율
- 사용자 승인 없는 파일·원격 변경: 0건
- 민감정보 노출 사고: 0건

## 1단계 출시 범위

첫 구현에서는 다음 범위만 출시한다.

- OpenAI 호환 API Provider 1개
- 저장소별 1개 활성 채팅 세션
- 기존 `ai-context` 자동 주입
- 스트리밍 답변
- API 키 서버 환경변수 설정
- timeout·토큰·응답 오류 처리
- 대화 초기화와 문맥 보기
- AI는 읽기 전용 답변만 제공

파일 수정, 셸 실행, 자동 테스트 재시도는 1단계에서 제공하지 않고 2~4단계의
승인·권한 기반으로 추가한다.

## 단계 간 의존성

```text
1 AI 연결
  → 2 읽기 도구
  → 3 승인 가능한 patch
  → 4 검증 루프
  → 5 편집기·터미널
  → 6 멀티 프로젝트·권한·감사
```

각 단계는 문서 작성만으로 완료하지 않는다. 기능 테스트, 실패 경로 테스트,
민감정보 비노출 테스트, 승인 경계 테스트와 실제 브라우저 스모크를 통과해야
완료로 표시한다.
