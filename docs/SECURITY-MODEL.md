# fl-git 보안 모델

이 문서는 `fl-git`을 내부용으로 운영할 때의 기본 경계와, 외부 접속을 허용할 때
반드시 추가해야 하는 보안 요구사항을 구분한다.

## 1. 기본 운영 모델: 내부용 로컬 서버

현재 제품의 기본 대상은 개발 서버 또는 개인 컴퓨터에서 본인만 사용하는 내부용
환경이다.

- HTTP 서버는 `127.0.0.1`에만 바인딩한다. LAN·인터넷에 직접 공개하지 않는다.
- 저장소 접근 범위는 `FL_GIT_ROOTS`로 제한하며 기본값은
  `/home/kim/kim/projects`이다.
- `FL_GIT_ROOTS`는 콜론(`:`)으로 구분한 실제 디렉터리 목록이며 `*` 와일드카드는
  허용하지 않는다. 요청 경로와 허용 루트는 `pwd -P`로 물리 경로를 확인한 뒤 비교한다.
- Git 명령은 제품이 정의한 작업만 허용하고, 임의 셸 명령 입력창은 제공하지 않는다.
- `push`, `pull`, Stage 취소, 브랜치 삭제 등 상태를 바꾸는 작업은 확인 절차를 둔다.
- 파일 뷰어는 `.env*`, SSH·AWS·GnuPG 키, `pem/p12/jks` 계열 키 파일,
  `credentials`, `npmrc`, `netrc` 등 민감 파일을 거부한다.
- GitHub 인증은 기존 `gh auth`·OS 키링을 사용하며 토큰을 파일·URL·화면·로그에
  기록하지 않는다.
- 서버 자동 시작을 추가하더라도 서비스는 사용자 권한으로 실행한다.

내부용은 "인증이 없어도 된다"는 뜻이 아니다. 로컬 바인딩과 OS 계정 경계가
현재의 1차 인증 경계이며, 다른 사용자가 접속할 수 있는 환경으로 바뀌면 외부용
모델로 전환해야 한다.

## 2. 외부 접속용 모델

`0.0.0.0` 바인딩, 공유 서버, 원격 접속, 역방향 프록시 공개를 하기 전에는
다음 항목을 추가하고 검증해야 한다.

### 필수 추가 항목

1. 사용자 인증: 세션 또는 OIDC 로그인과 만료·로그아웃을 제공한다.
2. 권한 관리: 사용자별 저장소·브랜치·읽기/쓰기/관리자 권한을 분리한다.
3. HTTPS: TLS를 적용하고 평문 HTTP 외부 접속을 차단한다.
4. CSRF·세션 보호: CSRF 토큰, SameSite 쿠키, 보안 쿠키, 요청 출처 검증을 적용한다.
5. 입력 검증: 저장소 경로, 파일 경로, 브랜치명, 커밋 메시지를 검증하고 경로 탈출과
   셸 주입을 차단한다.
6. 비밀정보 보호: GitHub 토큰은 전용 비밀 저장소에 보관하고 로그·응답·에러에
   노출하지 않는다.
7. 작업 승인: Push, Pull, 강제 변경, 삭제는 재인증 또는 명시적 승인 절차를 둔다.
8. 감사 로그: 로그인, 저장소 선택, 파일 열람, Stage, Commit, Push, Pull, 삭제를
   사용자·시각·저장소·결과와 함께 기록한다.
9. 운영 방어: 요청 속도 제한, 최대 파일 크기, 업로드 제한, 보안 헤더, 백업·복구
   정책을 적용한다.
10. 배포 점검: 외부 공개 전 보안 테스트와 의존성 점검을 통과시킨다.

## 3. 공개 전 금지사항

- 현재 내부용 인증 경계만으로 인터넷에 공개하지 않는다.
- `FL_GIT_ROOTS=*`를 외부 서비스의 기본값으로 사용하지 않는다.
- 임의 셸 실행 API를 추가하지 않는다.
- GitHub 토큰을 브라우저 localStorage, 저장소 파일, `.env` 커밋에 넣지 않는다.
- 외부 공개를 내부용 자동 시작 기능과 같은 설정으로 처리하지 않는다.

## 4. 구현 순서

1. 내부용: localhost 바인딩, 저장소 allowlist, 민감 파일 차단, 확인창을 유지한다.
2. 외부용 준비: 인증·권한 모델과 감사 이벤트 스키마를 먼저 확정한다.
3. 외부용 구현: HTTPS 역방향 프록시, 인증, 권한, CSRF, rate limit을 추가한다.
4. 검증: 비인가 저장소 접근, 경로 탈출, 셸 주입, 토큰 노출, CSRF, 권한 우회를
   테스트한 뒤에만 외부 공개를 허용한다.

현재 `fl-git`은 1번 내부용 모델을 기준으로 하며, 외부용 공개 서비스로 간주하지
않는다.
